## 5. 置顶评论

先在 DSH Desktop 里执行：

```
dsh plugin --profile desktop add github:No1064/dsh-web-browser
```

装完重启 DSH，左上角菜单点「浏览器」，地址栏输 chat.deepseek.com 回车，就能在 DSH 里用网页版 DeepSeek 了；标签页背景在起始页的「管理」里换。
源码和更新：https://github.com/No1064/dsh-web-browser
用得上的话顺手点个 Star，以后找更新方便。

## 6. 发布建议

**发布时间段**
- 首发：工作日 21:00–22:30（开发者/DeepSeek 用户下班后刷手机的高峰，30 秒演示类在这个时段完播更好）
- 备选：工作日 12:10–13:00（午休）
- 周末：10:00–11:30
- 避开：18:00–19:00 通勤时段（完播率低，和娱乐内容抢不过）

**封面选帧**
- 首选「DeepSeek 聊天页开在 DSH 面板里 + 左侧菜单「浏览器」高亮」的帧（约 9–12s，对应「DeepSeek 常驻」那段）：一眼看懂「网页版 DeepSeek 长在 DSH 里」，缩到 feed 尺寸时还能认出招牌。
- 次选换背景那段（约 14–19s）：画面好看，但截图里已经有四种背景选项和说明小字，1080×1440 裁切时容易糊，必须裁紧、只留图片背景 + 2–3 个选项。
- 不选片尾 CTA 帧（有安装命令和 GitHub 字样，和封面字打架），不选口播张嘴的帧。
- 选帧原则：画面稳定、口播暂停、画面里没有和封面重复的大字幕。

**是否叠热门 BGM**
- 不叠，用原声发布。成片已经是配音 + 原创 BGM，30 秒里口播信息密度大，热门 BGM（尤其中文歌、带人声的热门神曲）会跟云希抢频段，也容易让观众以为是娱乐内容划走。
- 一定要再配一层的话：只加无人声 lo-fi/轻电子，音量压到明显低于人声（约 -20 ~ -24dB），发布时仍选「原声」，方便别人复用你的音频。
- 热门 BGM 不保证额外流量，反而可能被归到同质化内容里。

**评论区怎么引导 Star**
- 置顶评论放安装命令 + 完整仓库地址 + 一句网页版用法（地址栏输 chat.deepseek.com）；地址被限流就改成「GitHub 搜 dsh-web-browser」，别反复贴。
- 不刷「求三连」「求 Star」，用价值交换的说法：「用得上的话点个 Star，以后更新你能收到。」
- 预备 FAQ 回复：
  - 「要另外装客户端吗？」→ 不用，就在 DSH 的内置浏览器面板里开网页版；登录按网页版自己的流程来。
  - 「Windows / macOS 能用吗？」→ 插件依赖 DSH Desktop 的桌面端 webview 桥，具体系统支持以 DSH Desktop 为准，不替它承诺。
  - 「背景怎么换？」→ 起始页点「管理」，背景支持默认渐变、纯色、图片 URL、本地图片。
- 负面评论（占内存、卡顿、为什么不做手机版）不删不杠，统一回「可以到仓库提 issue」，把讨论引到 GitHub。
- 发布后 1 小时内尽量逐条回评，互动会带一波推流；可以引导「转给同样在用 DSH 的同事」，但不做任何刷量动作。
